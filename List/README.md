# C++ list 知识整理

`std::list` 是标准库中的双向链表容器。它用节点保存元素，每个节点额外保存前后指针，因此插入和删除不要求元素连续存放，也不会因为插入而搬迁已有元素。

本章以 **C++20** 为基准，`main.cpp` 是本章练习入口，目前只包含头文件与空的 `main()`，边学边往里补代码。

## 1. 基本特点

```cpp
#include <list>

std::list<int> numbers;
```

`list` 是类模板，`std::list<int>` 与 `std::list<double>` 是不同类型。

- 元素存放在各自独立的节点中，节点之间用指针相连，**不保证连续存放**。
- 不支持随机访问，取第 `n` 个元素需要从头或尾逐个移动。
- 在已知位置插入、删除一个元素是常数时间，并且不会使其他元素的迭代器失效。
- 每个元素都要额外保存两个指针，空间开销比 `vector` 大。

一个只保留核心成员的简化模型：

```text
std::list<int> l{10, 20, 30}

head → [prev|10|next] ⇄ [prev|20|next] ⇄ [prev|30|next] → nullptr
```

节点之间的连接关系由容器维护，源码里看不到、也不应该依赖节点类型和指针布局。

## 2. 定义与初始化

```cpp
#include <list>

std::list<int> a;                       // 空容器
std::list<int> b(5);                    // 5 个 int，默认分配器下均为 0
std::list<int> c(5, 10);                // 5 个 10
std::list<int> d{1, 2, 3, 4};           // 4 个指定元素
std::list<int> e(d);                    // 复制 d 的元素
std::list<int> f(d.begin(), d.end());   // 迭代器区间构造

int arr[] = {7, 8, 9};
std::list<int> g(arr, arr + 3);
```

圆括号与花括号的差别与 `vector` 相同：`std::list<int> x(3, 5)` 是三个 5，`std::list<int> y{3, 5}` 是两个元素 3 和 5。

## 3. 元素访问

| 接口 | 含义 | 使用条件 |
| --- | --- | --- |
| `l.front()` | 第一个元素 | 容器非空 |
| `l.back()` | 最后一个元素 | 容器非空 |
| `l.begin()` / `l.end()` | 首元素 / 尾后位置 | `end()` 不可解引用 |

`list` **没有** `operator[]`、`at()`、`data()`。按序号取元素只能自己移动迭代器：

```cpp
// 取第 3 个元素（从 0 开始）：O(n)
auto it = l.begin();
std::advance(it, 3);
std::cout << *it << '\n';
```

C++11 起可用 `std::next(l.begin(), 3)`，语义相同，对 `list` 仍是线性开销。

## 4. 遍历与迭代器

```cpp
for (auto& x : l) {          // 修改元素
    x *= 2;
}

for (const auto& x : l) {    // 只读，避免复制
    std::cout << x << ' ';
}

for (auto it = l.rbegin(); it != l.rend(); ++it) {
    std::cout << *it << ' '; // 反向遍历
}
```

`list` 的迭代器是**双向迭代器**：支持 `++`、`--`、`*`、`==`，**不支持** `it + n`、`it2 - it1`、`<` 比较。需要按位置移动时用 `std::advance` 或 `std::next` / `std::prev`。

范围 for 遍历 `list` 时进行插入、删除同样是危险写法：遍历依赖当前节点的 `next` 指针，删除当前节点后继续使用保存的迭代器会出问题。需要边遍历边删除时，用显式迭代器接住返回值（见第 5 节）。

## 5. 插入与删除

### 5.1 常用接口

```cpp
std::list<int> l{1, 2, 3};

l.push_back(4);        // 尾部追加
l.push_front(0);       // 头部插入
l.emplace_back(5);     // 尾部原地构造
l.emplace_front(-1);   // 头部原地构造

l.pop_back();          // 删除尾部元素，不返回
l.pop_front();         // 删除头部元素，不返回

auto it = l.insert(l.begin(), 100); // 在迭代器位置前插入
l.insert(l.end(), 2, 7);            // 插入 2 个 7
l.erase(it);                        // 删除单个元素
```

`insert` 返回指向新插入元素的迭代器，`erase` 返回被删元素之后的迭代器。

### 5.2 边遍历边删除

```cpp
std::list<int> l{1, 2, 3, 4, 5, 6};
for (auto it = l.begin(); it != l.end();) {
    if (*it % 2 == 0) {
        it = l.erase(it);   // 接住返回的新位置，不再递增
    } else {
        ++it;
    }
}
// l 为 {1, 3, 5}
```

C++20 还可以直接：

```cpp
std::erase(l, 3);                                   // 删除所有等于 3 的元素
std::erase_if(l, [](int x) { return x % 2 == 0; }); // 删除所有偶数
```

这两个函数由 `<list>` 提供，逐个节点删除，整体线性复杂度。

`pop_back()` / `pop_front()` 和单元素 `erase()` 都必须保证容器非空。

## 6. splice、merge、sort 与 unique

这几个成员函数是链表结构的优势所在，普通顺序容器没有对应操作。

```cpp
std::list<int> a{1, 4, 5};
std::list<int> b{2, 3};

a.splice(a.begin(), b);       // 把 b 的全部节点接到 a 开头，b 被清空
// a 为 {2, 3, 1, 4, 5}，b 为空

std::list<int> c{6, 7};
a.splice(a.end(), c, c.begin()); // 只搬 c 的第一个节点

a.sort();                     // 成员 sort，升序
a.sort(std::greater<int>{});  // 降序
a.unique();                   // 删除相邻的重复元素，需先排序

std::list<int> x{1, 3, 5};
std::list<int> y{2, 4, 6};
x.merge(y);                   // 合并两个已排序链表，y 被清空
```

要点：

- `splice` 只改指针，不复制、不移动元素，因此不会使指向被搬运元素的迭代器失效。
- `std::sort` 要求随机访问迭代器，**不能用于 `list`**；必须用成员函数 `l.sort()`，复杂度为 O(n log n)。
- `merge` 假定两个链表都已按相同规则有序，合并后仍有序；无序时结果不符合预期。
- `unique()` 只合并**相邻**的相等元素。想删除所有重复值，先 `sort()` 再 `unique()`。

## 7. 迭代器失效规则

| 操作 | 失效规则 |
| --- | --- |
| 插入（`insert`、`push_back`、`push_front`、`emplace_*`） | 不使任何迭代器失效 |
| 删除（`erase`、`pop_*`、`clear`） | 仅被删除元素的迭代器失效 |
| `splice` | 不使任何迭代器失效（被搬运元素的迭代器仍指向同一元素，只是属于另一个容器） |
| `merge` | 仅被合并元素的迭代器含义改变（归属变化），不失效 |
| 赋值、`swap`、`assign` | 视操作而定，旧迭代器不应继续使用 |

这是 `list` 与 `vector` 最关键的区别：`vector` 插入可能整体搬迁，`list` 只动指针。因此需要“长期持有某个元素位置”时，`list` 的迭代器是稳定的。

不过迭代器稳定不等于访问安全：被删除元素的迭代器一定失效，不能继续使用。

## 8. 与 vector 的对比

| 对比项 | `std::list<T>` | `std::vector<T>` |
| --- | --- | --- |
| 内存布局 | 节点分散，不连续 | 元素连续 |
| 随机访问 | 不支持，O(n) | 支持，O(1) |
| 已知位置插入/删除 | O(1) | O(n) |
| 插入后迭代器 | 不失效 | 可能全部失效 |
| 头部插入 | O(1) | O(n) |
| 每元素额外开销 | 两个指针（+ 可能的对齐填充） | 通常没有 |
| 缓存友好度 | 差 | 好 |
| 排序 | 成员 `l.sort()` | `std::sort` |
| 适用场景 | 频繁在已知位置插入删除、需要稳定位置 | 默认首选，随机访问与批量处理 |

实际经验：**默认选 `vector`**。元素小、访问频繁时，连续存储带来的缓存优势通常远大于插入删除的移动成本。只有在元素较大、插入删除位置已知且频繁时，`list` 才更有优势。

## 9. 常见误区与自测

| 误区 | 正确理解 |
| --- | --- |
| `list` 支持 `l[i]` 下标访问 | 不支持，只能通过迭代器逐个移动 |
| `list` 的迭代器可以 `it + 3` | 双向迭代器不支持 `+`，用 `std::next` / `std::advance` |
| 用 `std::sort(l.begin(), l.end())` 排序 | 编译不通过，必须用成员 `l.sort()` |
| `splice` 会复制元素 | 只改指针，元素本身不移动、不复制 |
| 插入元素会导致其他迭代器失效 | 不会，`list` 插入不使任何迭代器失效 |
| `unique()` 能删除所有重复值 | 只处理相邻重复，通常先 `sort()` |
| `pop_front()` 返回被删元素 | 不返回，需先读 `front()` |
| 链表一定比 `vector` 快 | 只在特定插入删除模式下更快，访问和遍历通常更慢 |

自测问题：

1. `std::list<int> l(3)` 与 `std::list<int> l{3}` 的元素分别是什么？
2. 为什么 `list` 的迭代器不能写 `it + 1`？应该用什么替代？
3. 在 `l` 中间插入一个元素后，指向其他元素的迭代器是否仍然有效？
4. `std::sort` 为什么不能用于 `list`？
5. `splice` 与 `insert` 传入另一容器迭代器区间有什么本质区别？
6. 删除一个元素后，`erase` 返回什么？为什么遍历删除时要接住它？

参考答案：

1. 前者是 3 个值为 0 的元素，后者是 1 个值为 3 的元素。
2. 它是双向迭代器，只保证前后移动；替代写法是 `std::next(it, 1)` 或 `++it`。
3. 有效。`list` 插入只改变指针连接，不搬迁元素，不使其他迭代器失效。
4. `std::sort` 要求随机访问迭代器，`list` 只提供双向迭代器。
5. `splice` 只把节点挂到另一条链上，O(1)、不复制不移动；区间 `insert` 需要逐个复制或移动元素。
6. 返回被删元素之后的迭代器；接住它可以继续遍历，否则递增已失效的迭代器是未定义行为。
